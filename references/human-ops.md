# 仿人实验操作与证据保真

执行实验、补做步骤、采集截图或复核证据时读本文件。它约束的是**过程如何发生、证据如何呈现**，不改变写作、模板和独立审查链路。

课程实验要的是忠实轨迹（faithful trajectory）：按实验指导/报告要求一步一步做，并留下对应截图。模型常见的偏差是结果黑客（outcome hacking）——用工程师捷径证明“已经做成”，于是误解指导书、跳步导致必截帧变少，或用 CLI/哈希/脚本冒充 GUI 操作。下面把可复用的原则写死在执行卡之前；具体到某一步的禁令由该步 Step Card 的 `forbidden_shortcuts` 实例化，见 [禁止捷径目录](forbidden-shortcuts.md) 与 [Step Card 与冻结](step-cards.md)。

**来源标记**：`[来源:lab-report]`、`[来源:Bocchiid]`、`[来源:Anthropic-CU]` 表示已在对应仓库/文档读到原文或同义表述；`[推断/扩展]` 表示由同一原则推广、两仓未逐字写出。标记不是证据，不能据此声称某句已存在于旧版仓库。

## 1. 硬原则

### 1.1 字面优先于最优（Literal over optimal）

1. **指导书/已确认意图的字面步骤优先于更优、更快、更“正确”的工程师做法。** 发现更优解时，记入差异说明、改执行卡并**重新冻结**；禁止 silent shortcut（静默捷径），也禁止“先做完再补卡”。`[推断/扩展]`（与用户意图一致；Bocchiid 有“不要为了好自动化把 GUI 换成 CLI”的同族表述。）
2. **过程分 ≠ 结果分（Process ≠ Outcome）。** 实验“其实做成了”但缺少卡规定的过程证据/中间验收点 → **过程失败**，不得进入写作或宣称步骤完成。`[来源:Bocchiid]` L1 全通过才交 writer；`[来源:lab-report]` 历史成功或截图不能代替本轮证据。
3. **GUI / CLI 证据不可互相冒充（Non-substitution）。** 指导书要界面/按钮/对话框 → `modality=gui`（或 mixed 且主证据仍是 GUI）。CLI、哈希、脚本只可作**后台自检**，不得替代报告主证据，也不得写进“学生操作步骤”冒充过程。`[来源:Bocchiid]` planner：“不要为了好自动化把 GUI 证据换成 CLI；证据保真优先。”operator 禁止：“不用 CLI 输出冒充 GUI 截图。”`[来源:lab-report]` 不默认将哈希画面当主要证据；不用 `cat` 或按行输出替代编辑器查看。
4. **“存在 / 可打开 / 字节一致”分结论。** 见文件 ≠ 内容完整 ≠ 哈希一致，分别举证。`[来源:lab-report]` SKILL.md 与行为场景“下载呈现与完整性证明分开”。
5. **必截帧 = 执行卡并集，不是模型主观的“关键”。** `screenshot_required=true` 的步骤一张都不能少；中间验收点不可合并跳过。旧版“截关键帧，不截每个点击”容易被钻空子，现已收紧为“截取已冻结执行卡中 `screenshot_required` 的必截点；不截无意义的每个滚动/点击；不得合并或跳过卡上的中间验收点”。`[来源:lab-report]` 历史表述需收紧；`[来源:Bocchiid]` 阶段证据组逐张核对 `must_include`；`[来源:Anthropic-CU]` 每步后截图并评估是否成功，未确认不得下一步。
6. **后台工具可用，展示必须像学生做。** 可用命令定位、校验或做后台核验；**报告展示**仍走编辑器/资源管理器/指导书指定的 GUI。不为截图重绘、不伪造编辑器/终端图。`[来源:lab-report]` 行为场景“自然代码截图不限制后台工具”。
7. **不假设成功 / 不假设“已经做过”。** 动作后必须观察；旧截图只证明旧状态；环境变了要重采。`[来源:Anthropic-CU]` “After each step, take a screenshot and carefully evaluate…”；`[来源:lab-report]` 旧证据/环境变更相关条目。
8. **具名工具就是模态（Tool name binds modality）。** 指导书/附步骤写 Postman、Wireshark、MiniEdit 等具体工具时，主证据必须是该工具窗口；`curl`、`Invoke-RestMethod`、`tshark` 同族 CLI 只能后台自检，不得作为报告主证据，也不得写成“学生用 curl 完成 Postman 步骤”。`[来源:lab8-iter]`
9. **对象清单绑定（Object-set binding）。** 指导书写明的节点集合（如 `c0+s1/s2/s3+h1–h6`）、主机名、接口或文件必须进执行卡 `objects`/`must_include`；禁止用同实验的另一拓扑（如进阶 `1s3h`）冒充基础拓扑证据。`[来源:lab8-iter]`
10. **交互提示符要像该环境（Prompt fidelity）。** 交互式学生终端须显示符合环境的提示符（如 `ubuntu@sdnhubvm…$`），不得用 `bash-4.3$` 等非约定提示符冒充；指导书分多步时，不得用分号/一行批量命令合成一屏，除非指导书本身就是一条命令。`[来源:lab8-iter]`
11. **报告标注默认关闭（Annotation opt-in）。** 红框/箭头默认不画；用户明确要求时才可加，且不得遮挡关键字段、框线大致轴对齐。MiniEdit 控制链路等软件自带红虚线不算报告标注红框。`[来源:lab8-iter]`
12. **样式不得擅自升级（No style escalation）。** 允许区小节标题不得换为黑体或放大字号；与正文同中文字体、同字号，必要时仅加粗。样式规则见 [文档输出](document-output.md)，独审按 [审查清单](review-checklist.md) 核对。`[来源:lab8-iter]`
13. **跨轮证据失效（Round-bound evidence）。** 配置、MAC、拓扑或会话轮次变化后，旧图不得冒充本轮；旧图带过时标注或旧会话 MAC 必须重采。`[来源:lab-report]` B11.3 的收紧；`[来源:lab8-iter]`
14. **宿主机工具 + 客户机服务须如实说明（Forwarding disclosure）。** 允许宿主机 Postman 经本地端口转发访问客户机 REST，但正文须写明转发关系；主证据仍是 Postman 窗口，不是只交 curl 返回值。`[来源:lab8-iter]`
15. **破坏性操作先建检查点（Checkpoint before destruction）。** 清缓存、重置环境、删数据、改系统配置或网络、重装组件前，先建立可恢复的检查点（快照、备份、导出、原始文件副本），记录回滚方法和恢复时实际使用的文件/命令。检查点打不开、覆盖不到受影响对象，或回滚步骤无法复现时，不得执行破坏性动作；指导书未要求时先问或改用无损做法。`[推断/扩展]`
16. **变通必须申报，最终证据必须真实（Declare detours）。** 代理、注入脚本、改端口、临时模拟数据等绕路做法，先判断指导书/已确认意图是否允许；实施后必须在 `REVIEW_SELF` 的“变通申报”段逐项写明触发原因、偏离的步骤、作用对象、为何不能走原路径、最终真实证据出处和恢复方式。未申报的变通按隐藏捷径处理。变通只改变路径，不改变观测事实；最终证据不能来自变通产物本身，收尾要恢复端口、配置、代理、临时账号与注入脚本。`[推断/扩展]`

## 2. 仿人操作总则

- **按卡执行，不按记忆执行。** 先冻结 Step Card，再一次只做卡内的原子动作组。卡未要求合并时，不把“编译 + 运行 + 查看输出”压成一屏。
- **观察 → 动作 → 截图 → 验收。** 依赖视觉结果的动作不要盲目 batch；每组结束时截可取证的画面。`[来源:Anthropic-CU]`
- **真实窗口、真实路径、真实提示。** 截图应能看出当前程序、文件名/目录、命令或界面状态；不裁掉判断成功所必需的上下文。
- **失败如实保留。** 预期负结果、权限拒绝和错误提示是实验内容的一部分；不为了画面好看重跑成“成功”，不改关键输出。
- **环境归属清楚。** 宿主机、VM、容器、远端目标分开；截图保留可辨认的环境线索，不混用别处证据。`[来源:lab-report]`
- **原图保留。** 派生裁剪、红框/箭头只做不改变结果的展示处理；不 P 图、不用网图/生成图冒充实验截图。`[来源:lab-report]` `[来源:Bocchiid]`

## 3. 模态（modality）选择速查

| 指导书措辞 | modality |
| --- | --- |
| 点击、打开××窗口、在界面中、向导、Wireshark、任务管理器 | `gui` |
| 输入命令、执行 `gcc`/`ping`、查看终端输出 | `cli` |
| 先界面再命令验证（或相反），主证据仍跟指导书主路径 | `mixed`（主证据模态写在 `must_include`） |
| 插线、签字、现场拍照 | `manual` |

选择规则：**指导书写什么，主证据就是什么**。`mixed` 不是把 GUI 步骤换成 CLI 的通行证；如果报告主要展示界面，CLI 只能作为后台补充。指导书没有要求时，不因工具更方便而改模态。

## 4. 后台工具的允许边界

允许：
- 用命令定位文件、查看版本、检查端口/进程、做哈希或其它后台自检；
- 在可见终端中完成指导书本来就要求的编译、运行、`ping` 等命令步骤；
- 用脚本辅助整理证据清单、计算摘要或检查文件是否存在。

不允许：
- 用 `curl`/`wget`/包管理器静默安装代替指导书要求的下载页或安装向导；
- 用 `curl`/`Invoke-RestMethod` 等 CLI 输出冒充指导书指定的 Postman（或其它具名 GUI）窗口；
- 用 `tshark`/`tcpdump` 文本、`tasklist`/`Get-Process`/`ps` 文本、`cat`/`sed` 输出冒充 Wireshark、任务管理器或编辑器截图；
- 用哈希画面代替“下载/打开文件”的过程证据；
- 把后台核验结果自动写成报告中的“学生操作步骤”；后台额外核验不自动写入报告。`[来源:lab-report]`
- 伪造终端文本、编辑器 chrome 或把生成图当真实采集。`[来源:lab-report]` `[来源:Bocchiid]`

后台工具的作用是**帮助确认真实性**，不是**替代真实操作**。当后台结果与界面证据冲突时，先停下核对，不以后台结果压过界面事实。

## 5. 与 Step Card、Evidence Binder 的衔接

- 执行前必须有一份经用户确认并冻结的执行卡；卡内每步声明 `modality`、`tool`、`objects`、`screenshot_required`、`must_include`、`forbidden_shortcuts`。见 [Step Card 与冻结](step-cards.md)。
- 每完成一步，用 `complete_step` 记录证据文件与 `must_include` 逐项验收结果；缺证据、证据为空或 `must_include` 未标通过时拒绝完成。
- 全部步骤完成后封存证据绑定（`bind_evidence`），才允许 `submit_draft` 进入写作。没有登记执行卡的任务（例如纯审查任务）保持原有意图→成稿→独审流程。
- 发现指导书/环境有更优做法：先改卡、重新冻结并说明差异；不得先按捷径做完再回头补写卡片。

以上是执行阶段的硬边界；写作、模板和独立审查仍按 [SKILL.md](../SKILL.md) 与各自参考文档执行。

## 6. 自审记录与变通申报

制作方在提交独立审查前写一份自审记录 `REVIEW_SELF`（任务工作目录中的自审 MD，不是最终报告，也不能冒充独审）。独审先读它，再按白名单核对原始材料与当前成果。

“变通申报”段按步骤逐条记录，不是自由叙述；每项至少写：

- 触发原因与实际阻塞（错误原文、缺失能力或权限），不写“环境有问题”；
- 偏离了指导书/执行卡的哪一步，替代做法是什么（代理、注入脚本、改端口、模拟数据等）；
- 作用范围：涉及的对象、主机、端口、文件或请求；
- 为什么不能走原路径，是否取得指导书或用户允许；
- 最终证据由真实系统的哪一部分产生，路径或命令可定位；
- 收尾恢复：恢复了什么、如何确认已恢复，还留下哪些与默认环境不同的设置。

没有变通时明确写“无”，不留空让独审猜。变通申报不等于许可：未获允许的替代先停下询问；把变通产物当最终证据、或申报后不恢复环境，仍按 [禁止捷径目录](forbidden-shortcuts.md) B21 处理。破坏性操作另按 B20 先建检查点并记录回滚方法。

自审记录可以列出已核对项和未解决项，但不能替代独立审查，也不能证明证据真实。
