# 一份可溯源意图 MD

先读用户已有全部材料并澄清真实缺口，再输出。不是固定文档类型选择器，也不是冗长执行日志。内容与样式同份、分层逐条、不用表格；不为字数上限漏子要求。用户能连同原材料交给没有聊天历史的 AI 审，也能自己一眼看懂。

## 怎么提取

1. 从实际任务、模板栏目、评分要求和用户输入提取任务与验收；范例主要提供软样式参考，不能把范例主题/数据当本次要求。
2. 来源写全文件名、章节/栏目、实际条目或可定位段落，必要时引短原文。不编编号、不用“第五·1”等缩写。用户输入以实际约定内容及可核对的消息来源描述。
3. 每点写“要做什么—为什么/来自哪里—如何做”。关键项再写具体完成标准，不写“保证高质量”。重复要求可合并但保留各出处。
4. 自己推导的建议同样解释依据，例如某要求需要对照才能判断效果；标为“建议/待确认”，不能假称原文有此条。无依据的惯例不塞成硬约束。
5. 评分有最高档按最高档落实，无评分不虚构。摘要/参考文献等明确要求统一在本清单确认，不另外逐项问；未要求不擅加。真正冲突/不确定的项再讨论。
6. 样式写从实际模板读到的设置及用户偏好，区分中西文字体。范例整体风格可借鉴，不照搬固定页数、图数或全部排版细节。未知参数不编成模板值。

## 三、怎么推进
- 确认本清单 → 复用已有成果并补齐必要工作 → 写作排版 → 独立审查与修订复核 → 交付。
- 当前缺口：[实际缺口、自动补齐方式或确需用户提供的条件；没有则不写]。
- 待确认：[仅列真正待决事项，请用户确认当前版本或指出调整]。

用户确认后自动推进，不强制另行审批补齐计划或小样。确认记录保留实际消息/决定出处及对应版本，不能由 Agent 自己填写“用户同意”来制造授权。意图阶段的独立预审由用户选择；成稿独立审查是后续流程，不混为一项。

## 经验审核合并展示，决定分别记录

经验开启时，先读当前全部材料、独立提取约束，再按 [经验协议](memory.md) begin。不可变经验展示保存在私有根 reviews/；意图 MD 只写真正改变本轮要求的约束和 display_id 引用，不把队列、使用次数或核查时间放进已确认文件。仅方法选择变化时不改意图摘要；真正要求变化仍重新确认意图。

一次交互的合成例子：正文展示“本轮按模板 T1 的允许区修图题，固定封面及评分区保留”；同次附经验展示 D 中 L1@2 的具体方法、来源、条件、相对 L1@1 的变化及“批准长期规则”操作，另附 L2@1 的“本轮采用”操作。用户明确回复“确认本轮意图；L1 长期采纳，L2 暂缓”时，任务 approval 只绑定意图，memory_approval 只消费已展示的 L1@2；L2 不生效。若用户只说“报告要求确认”，不得推断经验批准。

条目多时分批呈现，提供本次 frozen 全部 ID/修订的查看入口；未展示项不参与批量批准。编辑后采纳先 revise、展示新正文和差异，再消费真实确认。采纳、暂缓、拒绝、暂停、撤销与删除的含义要写清；跳过只表示本次不审候选，不是永久关闭。收尾保存候选，不自动发起下一轮经验人审。
