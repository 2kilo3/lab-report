# 文档写作与输出检查

写作、格式修订或交付文档时使用。保持实际模板与已确认文体。普通实验报告不擅自扩写为技术部署说明书或论文；实验论文按其自身要求组织。

## 信息放在哪里

以下截图优先规则针对普通实验报告。论文等按已确认意图安排方法、数据、图表及必要代码，不用本节删掉其要求的文字或引用。

- **实验截图**：呈现实际目录切换/当前目录、运行文件和命令、程序交互、结果与必要对照；在最终页面尺寸下可读。不要求每张图重复完整环境或 `cd` 命令，已有提示符、前序图或可信关联能说明当前目录时不机械补拍。需要展示关键代码时打开实际文件，在编辑器/查看器中定位；不以 cat 或按行提取输出替代打开文件的展示，不把生成的代码图片冒充实验截图。正常终端编译、运行等实验操作照常使用。
- **正文**：简述本步骤任务、关键设计理由、现象及必要原因分析。图中已经可读的操作不逐字抄写；不罗列环境版本、路径、运行文件名和命令，也不加入“为保证真实性/可复现性”之类自证。
- **协议/算法设计**：任务要求的报文结构、字段含义与长度、边界处理、时序、算法逻辑仍需说明。它们不是应删的“实现细节”。表格、流程图等按任务和模板使用，不为追求少字删掉评分依据。
- **源码/工程等附件**：仅按任务提交要求交付，不能用附件存在替代报告要求的截图、流程图或解释。

例如模板要求“关键代码及解释”时，按用户截图偏好展示真实代码截图并简述其作用；要求流程图则保留流程图。若教师明确要求可复制代码与用户要求冲突，指出具体冲突，一次确认这一项。不能直接删除必需代码，也不能用大段文字替代证据。

已有报告的执行信息只在正文里、截图未覆盖时，先确认哪些确为必要证据，再补采相关截图。无法取得真实运行环境或原始材料时，继续可独立完成的文字和排版修订，但将相应证据项留为未完成，不能宣称报告全面达标。报告不放伪造图或假成功结论。

## 正文写作与语言复核

按 [academic-writing.md](academic-writing.md) 完成提纲、必要初稿、逐句去防御、连贯性润色和学术事实复核。该模块是课程适配的自包含规则，不需要每次访问上游；删除无关自辩，不删除必要条件、真实失败或必做任务。本文件负责信息分工与文档呈现，不另设一套写作标准。

## 样式来源、图片与图题

在允许编辑区域，明确用户样式要求优先，其余沿实际课程模板；模板未规定才使用本技能已明确的回退规则，不自行把固定字号、行距设为默认。意图 MD 中简述所采用样式与依据；同模板的范例主要软参考整体字体、排版与密度，其次参考写法/思路，不逐项硬性复制，用户提出的调整在后续落实。原始模板不改，不通过整篇重置样式实施局部要求。

图片按内容与最终页面可读性决定宽度，不全部等宽，不把窄图强撑满行，也不把代码/终端缩到难读。长代码用连续可读的真实截图；只保留必要关键帧和上下文。

每张独立实验截图都有图号和简短具体图名。普通报告只有真实拼接导出为一张图片才共用图题，不是并排就算一张。论文等模板要求组合图时允许按其子图规范组织，并明确各部分对应关系。图题先按模板，模板未规定时置于图下居中、不加粗、与图同页；编号统一，调整图片顺序后更新图号与引用。

按任务组织简短引入、相关截图及必要分析，不给每张图套一段重复解释。下载结果优先真实目录/文件画面，不默认展示哈希；后台完整性核验可以用合适技术方法，但文件出现或可以打开不能推出字节完全一致。

## 标题、中文与英文分别处理

1. 先从原模板识别同层级标题、正文和图题的实际格式；标题沿同级模板，不误套正文首行两字缩进；普通报告无明确标题规则时编号标题顶格，用户明确样式要求优先。检查整段左/start 缩进、firstLine/hanging 及 leftChars/firstLineChars 等字符单位覆盖、样式继承、前导空格和制表符，不是只清 firstLine。
2. 其余标题是否加粗、字号、颜色及间距以模板为准，不把“标题”统一处理成另一套大号粗体风格。正文是否首行缩进按模板，不把标题规则反过来应用到正文。
3. 分别提取模板中的中文和英文字体并落实，不从中文字体推断英文也相同。常见陷阱是中文宋体、英文实际要求 Times New Roman；后者只是核对提示，模板规定其他字体时不能强制替换。DOCX 同时检查样式和运行级的 ascii/hAnsi 字体、主题覆盖与 eastAsia 字体；修改本次允许区域的有效设置，不用全局替换破坏固定模板内容。
4. 截图中的字体属于原始证据，不重绘；公式和专用技术符号保留能正确表示符号的字体。字体不可用时报告实际替代情况，不能把回退显示称作目标字体实测。
5. 保存后检查真实页面及保护区。原始模板文件不改；报告中的固定要求、评分栏、封面固定文字等不能被共享样式联动覆盖。核对可见文字及运行级/继承格式：封面字号加粗、标题颜色、分节等均可能在文字未变时漂移。已证实的非授权漂移按可靠模板基线恢复，不将全文标题强制黑色，也不因原模板文件校验值不变就认定报告保护区未变。

## 表格

先遵实际模板及已确认要求；未规定时使用白底、黑字、黑色实际边框，含表头，不使用主题色或隔行底纹。使用原生可编辑表格，检查继承/条件样式、合并单元格与跨页渲染，辅助网格线不等于真实边框。不覆盖受保护模板区。

## 作者元数据在最后一次保存后验证

1. 从本次用户明确指定、报告封面或可信任务资料核实作者姓名，冲突或缺失时只问这一项。不从模板旧作者、机器用户名、邮箱或工具配置猜作者；多人报告保留核实的作者集合。
2. 在报告副本中设置人物身份字段：作者/创建者及最后修改者应为已核实作者，不出现模型、Agent 或工具昵称。不要将其个人信息写入可复用技能包。
3. 按实际格式检查：DOCX 的 core properties（creator、lastModifiedBy）；旧式 DOC 的摘要信息 Author/Last Saved By；交付 PDF 时检查 Author 及对应 XMP 作者字段。不用一个格式的检查替另一个格式背书。
4. Application、CreatorTool、Producer 等可能是实际软件生成器字段，不等于人物作者，不填人名冒充软件。清理自定义属性中无用的 Agent 标记，但不篡改无关历史事实、批注身份或法定声明，也不以元数据代替课程要求的 AI 使用披露。
5. 最后一次保存、格式转换、导出后重新读取实际交付文件；有些程序会重填作者或最后修改者。仅修改源文件属性不算完成。复核作者信息、模板保护和页面；未能读取某项时写明未验证，不填“通过”。
