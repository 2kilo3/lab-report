# 材料地图（MATERIALS_MAP）

材料地图是**意图确认前的硬门**：先读完全部材料，产出一份索引式地图；意图 MD 的每一条要求都必须能引用地图条目（`map_id`）。地图回答“哪份材料的哪一节、说了什么、影响哪条意图或哪步执行”，不是把材料全文搬进上下文。

## 1. 硬门与顺序

1. 收齐用户已给材料，登记来源清单；缺关键材料时先说明缺口，不凭常见课程套路补造要求。
2. 先通读全部材料，再按材料类型决定精读方式：任务书、模板、评分细则、实验指导/附步骤、范例、已有报告至少各有一份精读记录。关键材料应分给独立 subagent 或新 session 精读，返回索引条目；不要求每份都开新会话。
3. 汇总成 `MATERIALS_MAP.md`，放在任务工作目录，不放进技能安装目录。
4. 依据地图写一份可溯源意图；意图每条注明 `map_id`，确认后才实施。
5. 材料新增、替换或用户改要求时，先更新地图并登记新 `map_id`/修订号，再判断意图是否需要重新确认；旧地图条目不能继续证明新版本。

**出口条件（同时满足）**：地图文件存在；全部已给材料都有条目或明确的“未读/不适用”理由；意图每条硬要求至少引用一个 `map_id`；用户确认当前意图版本。缺一项都不得进入实施。

## 2. 地图是索引，不是全文缓存

- 每条只保留定位（文件、章节/页码/表格）、一句关键要求或事实、必要短引文（尽量不超过一两句）、影响范围。
- 不复制整章、整份模板样式表或大段指导书；需要精确原文时回读原文件，并以原文件为准。
- 短引文用于让审查者快速定位，不替代原文。地图里的概括如果与原文冲突，以原文为准并修正地图。
- 不把范例的主题、数据或结论写成本次要求；范例只记“可参考的整体样式/写法”，并标为软参考。

## 3. 条目字段

| 字段 | 必填 | 含义 |
| --- | --- | --- |
| `map_id` | 是 | 稳定编号，如 `M1`、`M2a`；修订用 `M1@2`，不复用旧编号表示新内容 |
| `material` | 是 | 实际文件名与类型（任务书/模板/评分/指导书/附步骤/范例/已有报告/环境说明） |
| `locator` | 是 | 章节、页码、表格、条目或可定位段落；不写“前面提到” |
| `kind` | 是 | `requirement` / `template` / `rubric` / `guide-step` / `example` / `existing-report` / `constraint` |
| `key_point` | 是 | 一句可核对的要求或事实；多条要求拆成多条 |
| `quote` | 建议 | 必要短引文，标点与原文一致 |
| `affects` | 是 | 影响的意图条目、交付物、执行步骤或样式区域；暂不清楚写 `待定` 并说明 |
| `reader` | 是 | 精读会话/子代理标识，或 `main`；便于复核是谁读的哪一段 |
| `status` | 是 | `indexed` / `deep-read` / `needs-user` / `not-applicable`；`needs-user` 必须写缺什么 |

`kind=guide-step` 的条目还要记录：指导书是否把它写成独立步骤、是否属于附步骤/addon、要求的工具或界面名称、对象清单（主机名、拓扑节点、文件名等）。这些字段直接喂给 [Step Card](step-cards.md) 的 `tool`、`objects` 与 `must_include`。

## 4. 骨架

```markdown
# 本次材料地图

- 材料根：[实际目录或用户给出的文件清单]
- 地图版本：1；生成时间：[实际时间]
- 未读/缺失：[没有则写“无”]

| map_id | material | locator | kind | key_point | quote | affects | reader | status |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| M1 | 任务书.docx | §2 实验要求第 1 条 | requirement | 需完成基础拓扑配置并截图 | “完成 c0+s1/s2/s3+h1–h6 的基础拓扑” | 意图 §一.1；S1–S3 | subagent-A | deep-read |
| M2 | 报告模板.docx | 第 2 页“实验步骤” | template | 该节标题与正文同字体同字号，仅加粗 | — | 样式 §二；写作 | main | indexed |
| M3 | 指导书.pdf | §4.2 Postman 验证 | guide-step | 用 Postman 向 REST 服务发请求并截响应 | “在 Postman 中发送 GET 请求” | 意图 §一.3；S4；must_include | subagent-B | deep-read |
| M4 | 评分表.xlsx | 第 3 行“过程完整性” | rubric | 最高档要求过程截图齐全 | — | 意图 §一.1 完成标准 | main | indexed |

## 待用户确认或缺口
- [只写真正影响实施的事项；没有写“无”]
```

## 5. 分发阅读的返回格式

给 subagent 或新 session 的任务只包含：材料路径、要回答的问题、返回字段（上表）和“不要复制全文、不要下结论代替主流程”。返回后由主编排者去重、合并同一条要求的多处出处，并把冲突标出，不擅自选一个当真。

- 精读 subagent 不确认用户意图、不写正文、不改模板、不执行实验。
- 返回的是索引和短引文；主流程需要原文判断时自己回读对应 locator。
- 两个读者对同一 locator 给出不同 key_point 时，回到原文核对，在 map 中保留冲突说明。

## 6. 反例

- 只写“已阅读全部材料”，没有 locator 和 `map_id`，意图无法回溯。
- 把指导书整节贴进地图，上下文膨胀且原文更新后地图悄悄过期。
- 意图条目引用 `M9`，地图里没有 `M9`，或 `M9` 对应的是范例而非要求。
- 把附步骤/addon 当成“可选优化”略过，既未写入意图，也未写“本次不做”及理由。
- 材料改版后继续用旧 `map_id` 证明新要求，不登记修订。
