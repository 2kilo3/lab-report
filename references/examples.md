# 写作校准示例

以下全部是假设情境，不是任何课程的已执行记录。只有前提中的证据真实存在、身份与状态核对通过，才能采用相应结论。示例中的主机名、图号和提示语必须换成实际证据，不能直接充当实验结果。

写作以截图和可核实操作为中心：交代做了什么、看到了什么、这能说明什么。不给截图看不见的结果，不用大段原理挤占实验过程。

## 1. 配置与验证：既不复述教材，也不只写“成功”

证据前提（假设）：任务要求验证两台实验主机的连通性；配置截图与测试截图来自同一轮实验，主机身份可核对，测试输出确实出现指定目标的回显响应。

- 太啰嗦：“计算机网络是现代信息技术的重要组成部分。TCP/IP 协议由多个层次构成……本实验具有重要的理论意义和实际价值。”
- 太空：“配置完成，测试成功，如图所示。”
- 合适：“在 HOST-A 中按要求设置网络参数后，向指定的 HOST-B 发起连通性测试（图 1）。输出出现该目标的回显响应，说明本次两台实验主机之间的连通性验证通过。”

边界：不能据此写“所有网络服务正常”或“互联网访问正常”。

## 2. 预期拒绝：报错也可能是正确结果

证据前提（假设）：任务要求验证普通账户不能修改受保护的测试文件；截图能识别账户、测试路径和操作，输出明确表示权限不足。

- 太啰嗦：“操作系统通过复杂的权限体系保障安全，权限管理历史悠久……这一机制充分体现了系统的优越性。”
- 太空：“操作报错，实验失败。”
- 合适：“使用普通账户尝试修改受保护的测试文件时，系统返回权限不足提示（图 2）。该拒绝符合任务规定的预期结果，说明本次账户对该文件的写入限制生效。”

边界：不把预期拒绝当作需要提权修复的故障；不推断其他账户或其他文件也经过验证。

## 3. 空白截图：说明证据不足，不猜结果

证据前提（假设）：某一步只留下空白终端截图，无法看到命令、输出或可识别的完成状态。

- 太啰嗦：“从界面的整体表现看，系统运行应该比较稳定。虽然截图未出现具体内容，但可以推测操作过程中没有遇到明显问题。”
- 太空：“没有输出，所以成功。”
- 合适（审查记录）：“现有截图未覆盖该步骤的命令和输出，不能据此判断操作是否完成或结果是否正确；该步骤仍缺可核对的证据。”

后续：在已获授权的环境和范围内补验、补采；若用户明确禁止重跑或环境不可用，保留缺口并说明阻塞。补证前不把此步写成已通过，也不在交付物中用假截图占位。

## 4. 前后对比：旧状态不能代替新结果

证据前提（假设）：已有调整前的配置截图，但调整后截图来自另一台实验主机；尚未取得同一主机调整后的配置及验证结果。

- 太啰嗦：“经过科学合理的参数优化，系统性能得到了显著提升，实验效果达到了预期目标，充分证明了方案的先进性和有效性。”
- 太空：“前后对比明显，优化有效。”
- 合适（审查记录）：“现有证据能确认调整前的配置，但另一张截图不属于同一实验主机，不能构成有效的前后对比。需补齐目标主机调整后的状态及验证结果，再判断本次调整的效果。”

边界：不能换个图注掩盖身份不一致，不能把旧运行结果当作新配置的验证。

## 从实验到成稿的最短检查链

1. 先读全部材料，再澄清；把实际要求短引文、完整出处、对应任务和验收标准写进一份简短要求 MD，包含默认样式，用户确认后再实施。
2. 核对并优先复用获准的本地环境；按任务完成一个代表性的完整小任务，真实取证、配各图图题和必要分析，按最终样式排版，让用户看实际小样，认可后再批量。
3. 正文围绕任务简述必要观察与原因，不逐图套段落；独立图各有图号图名，真实拼为一张才共用图题。
4. AI 核查内容、证据和客观格式并修好明确问题，再让人看实际报告。仅审查时不改正文。最终问题用一份简短 MD 按内容/样式分类。
5. 保存最终文件并从它渲染检查，核对作者属性后按课程要求交付可编辑 Word 与必要附件；PDF 只在要求时交，不拿旧预览证明新文档正确。

## 5. 执行信息放截图，分析留正文

证据前提（假设）：真实截图清晰显示客户端/服务端运行、接收完成；随后实际打开目标目录，能看到本次接收文件，并实际打开查看内容。

- 太啰嗦：“为保证实验可复现，本实验在某版本系统中切换到某绝对路径，运行某源文件编译得到的程序……所有结果均来自真实环境。”
- 太空：“文件传输完全正确。”
- 合适：“接收结束后，目标目录出现本次接收文件（图 5）；打开文件，可以查看传输内容（图 6）。”随后只补任务需要的结果分析。

边界：目录存在和能打开不能推出字节一致。任务若要求完整性验证，应真实进行必要比较并记录依据；后台可用哈希等方法，但不默认把校验日志当作自然截图的替代。实际只看到“发送完成”时，不能写已经接收并打开。各独立图仍各有图题。

## 6. 必需关键代码不能随“去文字”删除

证据前提（假设）：模板要求断点重传关键代码及解释；已有真实编辑器截图，能看清接收偏移处理和继续传输逻辑，另有运行截图验证恢复行为。

- 不合适：“用户不想看代码文字，因此删掉关键代码与解释，只保留传输成功截图。”
- 合适：插入实际关键代码截图并配图号图名，简述偏移如何决定续传起点；随后用真实恢复过程截图说明观察。按模板保留要求的流程图，不另加无关环境和路径清单。

边界：不能只靠代码截图证明运行正确；没有关键代码截图时保留待补证项，不能把删去源码块当作要求已满足。
